# OA协同办公平台 本地开发环境配置指南

本机 Windows 环境，采用**本地安装 MySQL + Redis + Nacos，IDEA 直接跑微服务，前端 npm run dev** 的方式开发。
Docker 演示环境已清理（相关改动保留在 `docker-deploy` 分支，需要时可随时重建）。

## 二、初始化数据库（一次性的）

本仓库 `sql/` 下的脚本均为**本地版**（`localhost`/`127.0.0.1`、Windows 路径），适合本机直接用。

### 1. 先确认本机 MySQL 可连

配置里数据库账号已写为 `root / 空密码`（与你本机一致，见第四节）。本机 root 密码为空，直接连即可：

```powershell
mysql -h 127.0.0.1 -P 3306 -uroot
```

- 如果你的 root 密码**非空**：导入后需到 Nacos 控制台把各 `ruoyi-*-dev.yml` 里的 `password:` 改成本机密码并发布。

### 2. 建业务库 `ry-cloud`

```powershell
mysql -h 127.0.0.1 -P 3306 -uroot -e "CREATE DATABASE IF NOT EXISTS \`ry-cloud\` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
```

### 3. 导入业务库（20 张业务表 + 11 张定时任务表 + OA 业务表）

```powershell
mysql -h 127.0.0.1 -P 3306 -uroot --default-character-set=utf8mb4 ry-cloud < sql\ry_20260417.sql
mysql -h 127.0.0.1 -P 3306 -uroot --default-character-set=utf8mb4 ry-cloud < sql\quartz.sql
mysql -h 127.0.0.1 -P 3306 -uroot --default-character-set=utf8mb4 ry-cloud < sql\oa_tables.sql
```

`oa_tables.sql` 为 OA 业务表（`approval_apply` / `approval_flow` / `schedule_event` / `contact_person` / `todo_item`）DDL + 演示数据，分别由 OA 各业务服务使用。

### 4. 导入配置库 `ry-config`（Nacos 用）

```powershell
mysql -h 127.0.0.1 -P 3306 -uroot < sql\ry_config_20260611.sql
mysql -h 127.0.0.1 -P 3306 -uroot --default-character-set=utf8mb4 < sql\ry_config_oa_20260819.sql
mysql -h 127.0.0.1 -P 3306 -uroot --default-character-set=utf8mb4 < sql\ry_config_oa_split_20260820.sql
```

第一个脚本自带 `CREATE DATABASE ry-config` + 全部 Nacos 3.x 表（`config_info`、`users` 等）+ 9 条若依配置；第二个为 OA 运行配置增量（网关 `/oa/**` 路由与 `/code` 白名单、`ruoyi-oa-dev.yml`）；第三个为 OA 服务拆分增量（新增审批/待办/日程/通讯录/聚合五个服务配置 + 网关按域拆分路由）。依次执行即可。

### 5. 验证

```powershell
mysql -h 127.0.0.1 -P 3306 -uroot -e "SELECT COUNT(*) AS biz_tables FROM information_schema.tables WHERE table_schema='ry-cloud'; SELECT COUNT(*) AS cfg_cnt FROM ry-config.config_info;"
```

预期：业务表 `25`（若依 20 张 + OA 5 张），配置条数 `14`（data_id 见下）。

> 14 条 data_id：若依原生 9 条（`application-dev.yml`、`ruoyi-gateway-dev.yml`、`ruoyi-auth-dev.yml`、`ruoyi-system-dev.yml`、`ruoyi-gen-dev.yml`、`ruoyi-job-dev.yml`、`ruoyi-file-dev.yml`、`ruoyi-monitor-dev.yml`、`sentinel-ruoyi-gateway`）+ OA 5 条（`ruoyi-approval-dev.yml`、`ruoyi-todo-dev.yml`、`ruoyi-calendar-dev.yml`、`ruoyi-contacts-dev.yml`、`ruoyi-portal-dev.yml`，均复用 `ry-cloud` 数据源、`typeAliasesPackage` 指向各域包名）。
>
> OA 相关配置均已并入上述两个增量脚本：网关 `/oa/approval|todo|calendar|contacts|dashboard|ai/**` 路由分别指向五个 OA 服务，`/code` 加入白名单（否则登录验证码 401）；`security.captcha.enabled` 与当前演示运行态一致为 `false`（免验证码），如需要验证码改回 `true` 即可。注：运行时配置变更请通过 Nacos 控制台/API 发布。

## 三、安装并启动 Nacos 3.0.2（单机）

### 1. 下载解压

从 Nacos 官方（https://nacos.io/download/nacos-server/ 或 GitHub releases）下载 **nacos-server-3.0.2.zip**，
解压到**无中文无空格**的路径，例如 `D:\env\nacos-server-3.0.2`。

> 版本说明：本仓库 `sql/ry_config_20260611.sql` 的表结构基于 Nacos 3.0.x，3.0.2 是与项目验证过的版本。
> 想用更新的 3.1/3.2 也可以，但需确认 schema 兼容；不建议用 2.x。

### 2. 修改 `conf\application.properties`

```properties
# 控制台端口：默认 8080 会与本机 gateway 撞，改成 18088
nacos.console.port=18088
# 注意：不要单独设置 server.port（3.x 会按 nacos.console.port 自动推导，手写反而会端口冲突）

# 连接本地 MySQL 的 ry-config 库
spring.datasource.platform=mysql
db.num=1
db.url.0=jdbc:mysql://127.0.0.1:3306/ry-config?characterEncoding=utf8&connectTimeout=1000&socketTimeout=3000&autoReconnect=true&useUnicode=true&useSSL=false&serverTimezone=UTC
db.user.0=root
db.password.0=

# 开发环境关闭控制台鉴权（客户端与控制台都免登录）
nacos.core.auth.enabled=false
# 下面三个是 3.x 必填项（3.0 起默认开启鉴权，即使关闭也要有值，否则启动会卡在交互输入）
nacos.core.auth.plugin.nacos.token.secret.key=<任意 32 位以上字符串的 Base64，如 VGhpc0lzTXlDdXN0b21TZWNyZXRLZXkwMTIzNDU2Nzg=>
nacos.core.auth.server.identity.key=serverIdentity
nacos.core.auth.server.identity.value=security
```

> 小版本差异提示：若你的 3.x 版本里没有 `nacos.console.port` 这个 key，以 `conf/application.properties` 内注释为准调整。

### 3. 启动（单机模式）

```powershell
cd D:\env\nacos-server-3.0.2\bin
startup.cmd -m standalone
```

需要 `JAVA_HOME` 指向 JDK 17+（本机 JDK 24 满足）。

### 4. 验证

- 日志出现 `Nacos started successfully in stand alone mode.`
- 控制台：http://127.0.0.1:18088 （鉴权已关，直接进入）
- 左侧"配置管理"应能看到上面 14 条 data_id；"服务管理"启动微服务后会出现 12 个服务。

## 四、关键配置速查（改这里才生效）

所有运行时配置都在 Nacos。**运行期改配置：用 Nacos 控制台在线改并"发布"，或 HTTP API 发布**（`POST /nacos/v1/cs/configs`）。⚠️ Nacos 3.x standalone 实际配置存文件系统（`data\tenant-config-data`），**直接改 MySQL `ry-config.config_info` 表不会生效**；仓库 `sql/ry_config*.sql` 只用于全新环境初始化，改完运行配置后可同步回脚本供下次初始化。

| 要改的东西 | 位置 | 当前值（本地版） |
|---|---|---|
| 数据库账号密码 | 每个 `ruoyi-*-dev.yml` 的 `datasource.url / username / password` | `root / 空密码`（本机 root 为空，已同步），url 为 `localhost:3306/ry-cloud` |
| Redis | 每个 `ruoyi-*-dev.yml` 的 `spring.data.redis` | `localhost:6379`，无密码 |
| 文件上传目录 | `ruoyi-file-dev.yml` 的 `file.path` | `D:/ruoyi/uploadPath`（Windows 本地，首次上传自动建目录） |
| 网关路由 | `ruoyi-gateway-dev.yml` 的 `routes` | `/oa/approval|todo|calendar|contacts|dashboard|ai/**` 分别指向五个 OA 服务；**改动后重启 gateway** |
| 验证码开关 | `ruoyi-gateway-dev.yml` 的 `security.captcha.enabled` | `false`（免验证码演示；改 true 需重启 gateway） |
| Nacos 地址 | 各模块 `bootstrap.yml` 的 `server-addr` | `127.0.0.1:8848`（本地无需改） |
| 各服务端口 | 各模块 `bootstrap.yml` 的 `server.port` | 见第一节表格（本地无需改） |

> 改了配置若没生效：控制台确认 group 是 `DEFAULT_GROUP` 并点了"发布"；改动 `application-dev.yml` 之类公共配置需重启相关服务。

## 五、后端启动（IDEA）

### 1. 导入工程

File → Open 选择根目录 `pom.xml`，作为 Maven 工程打开（等待依赖下载完成）。

### 2. 配置 JDK 与 Lombok

- File → Project Structure → Project SDK 选 JDK 17（或 24，已验证可跑）；Language level 选 17。
- Settings → Build, Execution, Deployment → Compiler → Annotation Processors → 勾选 **Enable annotation processing**（否则 Lombok 报错）。

### 3. 配置 Maven

Settings → Build Tools → Maven → Maven home path 填 `D:\Program Files\apache-maven-3.9.16`；User settings 用默认即可（走中央仓库）。

### 4. 首次构建公共模块

在项目根目录执行（安装 `ruoyi-common*` 等到本地仓库，**首次必须**）：

```powershell
mvn clean install -DskipTests
```

### 5. 启动微服务

每个模块的启动类 `Application`（`ruoyi-*` 各目录下），在 IDEA 里逐个 Run：

1. `ruoyi-gateway` → `RuoYiGatewayApplication`（8000）
2. `ruoyi-auth` → `RuoYiAuthApplication`（9200）
3. `ruoyi-modules/ruoyi-system` → `RuoYiSystemApplication`（9201）
4. `ruoyi-modules/ruoyi-gen` → `RuoYiGenApplication`（9202）
5. `ruoyi-modules/ruoyi-job` → `RuoYiJobApplication`（9203）
6. `ruoyi-modules/ruoyi-file` → `RuoYiFileApplication`（9300）
7. `ruoyi-modules/ruoyi-approval` → `RuoYiApprovalApplication`（9210，OA 审批）
8. `ruoyi-modules/ruoyi-todo` → `RuoYiTodoApplication`（9211，OA 待办）
9. `ruoyi-modules/ruoyi-calendar` → `RuoYiCalendarApplication`（9212，OA 日程）
10. `ruoyi-modules/ruoyi-contacts` → `RuoYiContactsApplication`（9213，OA 通讯录）
11. `ruoyi-modules/ruoyi-portal` → `RuoYiPortalApplication`（9214，OA 工作台聚合）
12. `ruoyi-visual/ruoyi-monitor` → `RuoYiMonitorApplication`（9100）

顺序不强制（都注册到 Nacos），建议先起 gateway 再起业务模块。
每个模块控制台出现 **`启动成功`** 即 OK；到 Nacos 控制台"服务管理"确认 12 个服务都在。

### 6. 验证后端

`http://localhost:8000` 有响应（未登录访问会走网关返回提示）即网关正常。

## 七、常见问题（FAQ）

1. **启动报连不上 8848** → Nacos 没起来或端口被占。确认 8848、9848 都在监听；`netstat -ano | findstr 8848`。此前 docker 的 nacos 已停，本机 8848 现在空闲。
2. **gateway 起不来，报 `Port 8080 was already in use` / "访问权限不允许"** → 本机 Windows 保留端口段 `8028-8127` 包含 8080，任何进程都绑不上。本项目网关已改为 **8000**（第一节有说明），确认你是从改后的代码启动的即可。
3. **gateway 日志反复刷 Sentinel `127.0.0.1:8718` 连接错误** → 本地没装 Sentinel 控制台（`bootstrap.yml` 里 `eager: true`），**不影响功能**，可忽略；想装再说。
4. **登录报验证码/Redis 相关错误** → 确认本机 Redis 6379 已启动，且 Nacos 各配置 `redis.host` 是 `localhost`。
5. **中文乱码** → 连接串已带 `characterEncoding=utf8`，导入 SQL 时命令行加 `--default-character-set=utf8mb4`。
6. **文件上传失败** → 检查 `ruoyi-file-dev.yml` 的 `file.path`（`D:/ruoyi/uploadPath`）可写；浏览器访问 `http://localhost:9300` 能通。
7. **IDEA 里 Lombok 报错** → 按第五节第 2 步开启注解处理。
8. **改了 Nacos 配置不生效** → **Nacos 3.x standalone 的配置实际存文件系统（`data\tenant-config-data`），直接改 MySQL `ry-config.config_info` 表不生效**；必须通过 Nacos 控制台在线发布，或用 HTTP API：`POST /nacos/v1/cs/configs?dataId=xxx&group=DEFAULT_GROUP&type=yaml&content=...`。改的是**网关配置（`ruoyi-gateway-dev.yml`）时，改动路由后需重启 gateway** 才会加载。
9. **登录报"用户密码不在指定范围"** → 后端要求密码明文长度 5~20（`UserConstants`），前端提交的是**明文**密码（RSA 加密仅用于"记住密码"cookie）。用接口/脚本调试时别传 MD5 或 RSA 密文，直接传明文 `admin123`。
10. **登录报 `No static resource auth/login`** → 网关路由失效。本机 8000 网关与 ERP demo 项目共享，**OA 与 ERP 都会启动 gateway 抢占 8000**；冲突时先停对方的 gateway 进程再启动本项目 gateway。
11. **OA 服务起不来，报 `Cannot find class: OaXxx`** → Nacos 中对应服务配置的 `typeAliasesPackage` 填错（例如出现 `com.ruoyi.oa.todo.todo`），修正后在 Nacos 重新发布并重启该服务。
12. **工作台统计/智能助手数据为空** → `ruoyi-portal` 通过 Feign 拉取四业务服务（approval/todo/calendar/contacts），确认这 4 个服务都已启动并注册到 Nacos。

## 八、Git 分支约定（本仓库）
